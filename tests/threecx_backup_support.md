# 3CX reader verification

Run `php tests/threecx_backup_parser.php` with PHP DOM/XMLReader/mbstring/zip enabled. The fixtures are synthetic and include invented credentials. Tests create private temporary files and remove them. They never connect to a PBX or SMTP service.

The native adapter recognizes only the verified legacy v14/v16 envelope `PhoneSystem/header/version`, `PhoneSystem/Gateways/{VoipProvider,Gateway}`, and `PhoneSystem/Tenants/Tenant/{DN,OutboundRules}`. One tenant is required. Core user fields come from `DN/Extension`; trunks join `DN/ExternalLine/Gateway` to provider `Name`, with credentials on the external line. An outbound rule must have one nonempty route and no extension/department restriction. Its provider must resolve to one external line. Inbound rules migrate only exact DIDs with the same destination in both office-hours and out-of-office-hours rules. Other behavior is listed in `unsupported`.

Evidence read during implementation:

- [Public MIT converter source](https://github.com/ninjanody/Elastix5Converter/tree/master/templates) includes `backupDb.xml` version `14.0.0.0` and original extension, external line, provider and outbound rule templates. The implementation was written independently; no customer data or external XML fixtures were copied into this repository.
- A [public converter artifact](https://github.com/QuendaltonBreed/Donegal3CX) contained a native XML envelope with version `16.0.1.273`. It was inspected in memory for tag paths and attribute names only. Credential values and customer records were not logged or retained.
- [Official 3CX setup documentation](https://www.3cx.com/docs/configure-pbx-automatically/) and its [official V20 setup sample](https://downloads-global.3cx.com/downloads/misc/setupconfig_v20.xml) describe the separate `SetupConfig` export. That export is clearly labeled and is never called a native backup. External `BackupFile` references are not fetched.
- [Official V20 Update 7 announcement](https://www.3cx.com/blog/releases/admin-system-management/) describes Backup & Restore V2. It does not publish the native archive/XML schema. Searches of official documentation and public code did not produce a verifiable native V20 fixture. Therefore V18/V20, unknown versions, encrypted containers and unfamiliar layouts return `supported=false`. A real V20 sample and version-specific mapping tests are required before enabling V20 migration.

`supported=true` means the envelope is recognized and some core configuration is safely mappable. It does **not** mean full restore or behavior parity. Any import must show warnings and unsupported records, require acknowledgement of omitted behavior, and leave trunks and inbound routes disabled for carrier review.

The parser has no extraction operation. It reads one root `*Db.xml`, `backupDb.xml`, or `setupconfig.xml` into memory. ZIP limits are 128 MB upload, 512 MB expanded metadata, 5,000 entries, and 200:1 compression for files over 1 MB. Configuration XML is limited to 8 MB, 32 levels, 100,000 reader nodes and 2,000 core records per category. Application upload limits may be lower. Unsafe paths, duplicate names, links, special files, encryption, unknown compression, malformed XML, DTDs, entities and unsupported namespaces are rejected. `preview()` uses field allowlists and exposes only presence flags for SIP usernames, authentication identifiers, passwords and voicemail PINs.
